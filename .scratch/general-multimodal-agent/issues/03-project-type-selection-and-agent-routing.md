# 03 — 项目类型选择与会话 agent 路由

**What to build:** 用户新建项目时可以在轻量弹窗里选择助手类型（天气助手 / 通用助手，默认天气助手），创建后类型不可改，重命名弹窗不暴露类型。每个会话按自己的类型路由到对应 runtime agent：通用助手项目的会话与 `generalAgent` 纯对话，天气项目的会话保持现有 `weatherAgent` 行为。切换活动项目不改变当前会话的 agent；空项目的欢迎区按类型区分——天气项目保持现有欢迎语和推荐问题，通用助手项目显示通用欢迎语、不含天气推荐。端到端效果：创建一个通用助手项目即可开始文本闲聊。

**Blocked by:** 01 — 后端并列注册通用助手 agent；02 — 工作区状态 v2：项目/会话类型与原地迁移

**Status:** ready-for-agent

- [ ] 新建项目弹窗（及任何其他项目创建入口）包含助手类型选择，默认天气助手；名称校验与错误展示行为不变
- [ ] 项目类型创建后不可改；重命名流程不暴露类型
- [ ] 聊天组件按当前会话的 `agentType` 推导 `runtimeAgentId`（`"weatherAgent"` / `"generalAgent"`）；会话生命周期内不切换 runtime agent；切换活动项目不影响当前会话路由
- [ ] 未分类会话按其捕获的类型继续路由到对应 agent
- [ ] 空状态按会话类型区分：天气保持现有欢迎语与推荐问题；通用助手显示通用欢迎语且无天气推荐；两种空状态都保留输入区
- [ ] 天气项目下既有会话的消息快照恢复、发送失败重试、历史分组等行为无回归
- [ ] 浏览器手工验证：新建通用项目 → 文本问答来自 generalAgent（无天气工具痕迹）；新建天气项目 → 行为与现状一致
- [ ] `pnpm test` 与 `pnpm exec tsc --noEmit` 通过
